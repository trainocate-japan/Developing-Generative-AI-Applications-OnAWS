# モジュール 7: 生成 AI アプリケーションコンポーネントの評価 - ハンズオンシナリオ

## シナリオ概要

あなたは、RAG チャットボット（M05 で構築）を本番投入する前に、その品質を定量的に評価する
役割を任されました。「どのモデルを選ぶか」「RAG の検索・生成は十分か」「レイテンシーとコストを
どう下げるか」を、メトリクスとテクニックで判断できるようになることが目標です。

## 学習目標

このハンズオンを完了すると、以下ができるようになります。

1. **モデルを優先順位で選ぶ**: コスト・品質・速度のトレードオフを実測で比較する
2. **RAG を評価する**: Ragas のメトリクス（忠実度・応答の関連性・コンテキスト適合率）を理解する
3. **レイテンシーとコストを最適化する**: プロンプトキャッシュ・レイテンシー最適化推論を使う
4. **評価データセットを扱う**: 質問・コンテキスト・応答・リファレンスの構造を理解する

## 評価の全体像

```
【モデル出力の評価】
  正解率メトリクス / 類似度メトリクス / HITL・LLM-as-a-Judge

【RAG の評価（Ragas）】
  検索: コンテキスト適合率 / コンテキスト再現率 / エンティティ再現率
  生成: 忠実度 / 応答の関連性 / ノイズ感度

【最適化】
  プロンプトキャッシュ / Intelligent Prompt Routing / レイテンシー最適化推論
```

## モデル選択の優先順位（例）

| モデル | 速度 | 品質 | コスト |
|-------|------|------|-------|
| 軽量モデル (Nova Lite) | 速い | 中 | 安い |
| バランス型 (Nova Pro) | 中 | 高 | 中 |
| 高品質 (Claude Sonnet) | 中 | 最高 | 高 |

## 使用する AWS サービス

- Amazon Bedrock（Converse API / プロンプトキャッシュ）
- Ragas（オープンソースの RAG 評価フレームワーク、`langchain-aws` 経由で Bedrock を利用）
