# モジュール 9: 生成 AI アプリケーションにおけるツールとエージェント - ハンズオンシナリオ

## シナリオ概要

あなたは、株価や天気などの「最新情報」を答えられるアシスタントを開発しています。
基盤モデルは学習時点までの知識しか持たないため、**ツール（関数呼び出し）**で外部情報を取得し、
さらに **エージェント**として自律的に推論・行動できるようにします。
フレームワーク（Strands）やプロトコル（MCP・A2A）の役割も整理します。

## 学習目標

このハンズオンを完了すると、以下ができるようになります。

1. **ツール使用（関数呼び出し）を理解する**: Converse API の `toolConfig` でモデルにツールを渡す
2. **ツール実行ループを実装する**: モデルの `toolUse` → 関数実行 → `toolResult` を返す流れ
3. **エージェントフレームワークを使う**: Strands Agents で同じことを少ないコードで実現する
4. **相互運用プロトコルを理解する**: MCP（ツール接続）と A2A（エージェント間連携）の違い

## ツール使用（関数呼び出し）の流れ

```
1. ユーザー: 「東京の天気は？」
2. モデル: toolUse { name: get_weather, input: {city: "東京"} } を返す
3. アプリ: get_weather("東京") を実行し結果を取得
4. アプリ: toolResult をモデルに返す
5. モデル: 結果を踏まえた最終回答を生成
```

## MCP と A2A の違い

| 観点 | MCP | A2A |
|------|-----|-----|
| やり取り | 単一エージェント/ツール接続 | 複数エージェント間 |
| 通信 | MCP サーバー/ホストで一元化 | ピアツーピア |
| 適合 | ツールオーケストレーション | 分散タスク委任・専門化 |

## 使用する AWS サービス

- Amazon Bedrock（Converse API のツール使用）
- Strands Agents SDK（`strands-agents`）
- MCP（Model Context Protocol）
