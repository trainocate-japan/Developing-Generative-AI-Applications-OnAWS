# モジュール 4: 一般的なアーキテクチャでの Amazon Bedrock API の使用 - ハンズオンシナリオ

## シナリオ概要

あなたはカスタマーサポート向けのチャットアプリを開発しています。
これまで学んだ Bedrock API を使って、代表的な**アーキテクチャパターン**（生成・要約・質問応答・会話）を
実装し、さらに「会話が続く」体験を実現するために**会話メモリ**を追加します。

## 学習目標

このハンズオンを完了すると、以下ができるようになります。

1. **4 つのアーキテクチャパターンを実装する**: 生成 / 要約 / 質問応答 / 会話
2. **推論モードを使い分ける**: オンデマンド / バッチ / プロビジョンドスループットの違いを理解する
3. **会話メモリを追加する**: 会話履歴を messages に積み重ねてコンテキストを維持する
4. **永続的なメモリを実装する**: Amazon DynamoDB に会話履歴を保存し、セッションを跨いで復元する

## アーキテクチャパターン

| パターン | 概要 | 例 |
|---------|------|-----|
| 生成 (Generation) | 指示から新しいテキストを生成 | レビュー・メール文面 |
| 要約 (Summarization) | 長文を短くまとめる | 記事・議事録の要約 |
| 質問応答 (Q&A) | 質問に答える | FAQ・ヘルプ |
| 会話 (Conversation) | 文脈を保った対話 | チャットボット |

## 会話メモリの考え方

```
1 往復目:  [user] -> [assistant]
2 往復目:  [user, assistant, user] -> [assistant]   ← 過去のやり取りを messages に含める
...
（DynamoDB に保存すれば、別セッションからも履歴を復元できる）
```

## 推論モードの比較

| モード | レイテンシー | コスト | ユースケース |
|-------|------------|-------|------------|
| オンデマンド | 低（秒） | リクエスト課金 | チャットボット・RAG |
| バッチ | 高（分〜時間） | 低コスト | レポート・分析 |
| プロビジョンドスループット | 低（秒） | モデルユニット購入 | 大規模・一貫負荷 |

## 使用する AWS サービス

- Amazon Bedrock（Converse API）
- Amazon DynamoDB（会話履歴の永続化）

## 所要時間

約 45 分

## 前提条件

- AWS CLI 設定済み / Python 3.12+
- モデルアクセス有効化済み: Amazon Nova Lite / Pro
- DynamoDB へのアクセス権限（`conversation_memory.py` で使用）
