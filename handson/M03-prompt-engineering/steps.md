# モジュール 3: プロンプトエンジニアリングの応用 - ハンズオン手順

## パート 1: プロンプトの構成要素を確認する（5分）

### ステップ 1.1: Bedrock プレイグラウンドで要素を意識する

Amazon Bedrock コンソール → Test playgrounds → Chat/Text（モデル: Nova Lite）で、
以下のプロンプトを送信します。4 つの要素（指示・出力インジケーター・コンテキスト・入力データ）を
意識しながら結果を観察してください。

```
サービスレビューの要約を書いてください。2 文で。
ストア: オンライン、サービス: 配送
レビュー: Amazon Prime Student は学生向けのお得なサービスです。送料無料と無料 2 日間配送が
魅力で、通常会員の半額でストリーミングや書籍も利用できます。
```

| 要素 | 上の例での対応 |
|------|--------------|
| 指示 | 「サービスレビューの要約を書いてください」 |
| 出力インジケーター | 「2 文で」 |
| コンテキスト | 「ストア: オンライン、サービス: 配送」 |
| 入力データ | 「レビュー: ...」 |

## パート 2: 3 つの基本テクニック（15分）

### ステップ 2.1: プロジェクトの準備

```bash
cd ~/handson/M03-prompt-engineering
```

### ステップ 2.2: テクニックを比較する

```bash
python prompting_techniques.py
```

出力を見ながら以下を確認します。

- **ゼロショット**: 例なしでも分類できる（大規模モデルほど有効）
- **フューショット**: 例を示すと、出力が「1 単語」に安定する
- **思考の連鎖 (CoT)**: 「計算過程を示してから」と促すと、途中計算を経て正解に至る

**議論**: 分類タスクでフューショットが有効なのはなぜか（出力形式の学習）。

## パート 3: プロンプトテンプレート（10分）

### ステップ 3.1: テンプレートを再利用する

```bash
python prompt_template.py
```

- 同じ `SUMMARY_TEMPLATE` を、`length`（1 文 / 3 つの箇条書き）だけ変えて再利用
- テンプレート化の利点（一貫性・再利用・テスト容易性・スケーラビリティ）を体感

### ステップ 3.2: Amazon Bedrock プロンプト管理（コンソール・任意）

本番運用ではプロンプトをコード外で管理できます。

1. Bedrock コンソール → **Prompt management** → **Create prompt**
2. `{{category}}` `{{text}}` `{{length}}` のような変数を含むテンプレートを作成
3. **Test variables** に値を入れてテスト
4. **Create version** でバージョンを保存（ロールバック可能）

## パート 4: クエリの分解（10分）

### ステップ 4.1: 複雑な要求を分割して処理

```bash
python query_decomposition.py
```

- 「ユーザー登録 REST API を作る」を、データモデル → エンドポイント → 検証 と分割
- 前ステップの出力を次ステップのコンテキストに渡し、一貫性を保つ

### ステップ 4.2: ベストプラクティスの適用

以下の「改善前 → 改善後」を意識してプロンプトを書き換える練習をします。

| ベストプラクティス | 改善前 | 改善後 |
|------------------|--------|--------|
| 具体的・明確に | ログインフォームを生成 | メール検証・パスワード強度・エラー処理を備えた React のログインフォーム |
| 役割を設定 | 脆弱性を調べて | あなたは経験豊富なセキュリティエンジニアです。この関数の脆弱性を特定してください |
| 区切りを明確に | （混在した文章） | 「コンテキスト:」「タスク:」に分けて記述 |
| 出力形式を指定 | コンポーネントを生成 | 関数コンポーネント・TypeScript・アクセシビリティ準拠・コメント付き |

## パート 5: まとめとナレッジチェック（5分）

### ナレッジチェック（スライド対応）

1. 例示せずに LLM へ指示するテクニックは？ → **ゼロショットプロンプティング**
2. プロンプトの主要要素でないものは？ → **トレーニングデータ**（要素は指示・コンテキスト・入力データ・出力インジケーター）
3. 大量データから関連文書を検索して回答の根拠にするテクニックは？ → **検索拡張生成 (RAG)**（M05 で実践）
