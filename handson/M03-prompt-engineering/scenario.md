# モジュール 3: デベロッパー向けプロンプトエンジニアリングの応用 - ハンズオンシナリオ

## シナリオ概要

あなたは社内開発ポータルの担当者です。開発者から「同じ Bedrock モデルなのに、人によって
出力の質にばらつきがある」という声が上がっています。そこで、**プロンプトエンジニアリング**の
テクニックを整理し、再利用可能なプロンプトテンプレートとして提供することにしました。

モデルの重みは変えずに、プロンプトの書き方だけで出力品質を引き上げる方法を学びます。

## 学習目標

このハンズオンを完了すると、以下ができるようになります。

1. **プロンプトの構成要素を理解する**: 指示・コンテキスト・入力データ・出力インジケーター
2. **3 つの基本テクニックを使い分ける**: ゼロショット / フューショット / 思考の連鎖 (CoT)
3. **プロンプトテンプレートを作る**: プレースホルダーで再利用可能なプロンプトを設計する
4. **クエリを分解する**: 複雑な要求をサブタスクに分割して順に処理する
5. **ベストプラクティスを適用する**: 具体性・役割設定・区切り・出力形式の指定

## プロンプトの共通要素

```
┌─────────────────────────────────────────┐
│ 指示 (Instruction)                        │  何をしてほしいか
│ コンテキスト (Context)                    │  背景情報
│ 入力データ (Input Data)                   │  処理対象
│ 出力インジケーター (Output Indicator)     │  出力の形式・長さ
└─────────────────────────────────────────┘
```

## 3 つの基本テクニック

| テクニック | 概要 | 向いているケース |
|-----------|------|----------------|
| ゼロショット | 例を挙げずに指示 | 大規模モデルでの一般的タスク |
| フューショット | 入出力例を提示 | 出力形式を揃えたいタスク（分類など） |
| 思考の連鎖 (CoT) | 中間推論ステップを促す | 計算・多段推論タスク |
